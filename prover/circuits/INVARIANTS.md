# Ring circuit invariants

This file lists each predicate the ring circuits in `prover/circuits` enforce, and the tests that cover it. It is a checklist kept by hand. The Go constraints decide what holds. A claim here that the code does not make is a defect of this file.

[Proof composition](../../docs/design/proof-composition.md) names the enforcer of each guarantee that crosses the ring proof, SPP's proof and the program. This file covers the circuit side of that argument. It names a program or SPP check only where a circuit predicate relies on it.

## Reading and maintaining the checklist

IDs are stable. Never renumber an id and never reuse one. A predicate the code drops keeps its row with the kind `retired`.

Each statement is one claim about every witness that solves the key. It says what holds, not how the code computes it. "Live" means a slot whose domain is the UTXO domain. "Zero key" means the nullifier key `Poseidon(0)`, `shared.ZeroNullifierPk`. "Ring note" means a live slot with a nonzero ring id, "default-ring note" a live slot with ring id zero.

Markers:

- `[x]` Covered. A positive test solves an honest witness, and a refusal test breaks the predicate and requires the refusal. Both were read.
- `[ ]` Partial. One of the two exists, or both exist and a case of the claim has no test. The row names what is missing.
- `[ ]` Missing. No test was found.

What counts as coverage:

- A positive case solves the full circuit, or a harness that calls the gadget under test.
- A refusal case changes one value, recomputes every statement element the change moves, and requires the refusal. `ringtest.RequireUnsolved` or `ringtest.RequireRefused` with a frame, and `ringkey.Bound.Refuse`, name the predicate. A refusal that names only `Define` or names no frame is weaker, and the row says so.
- A statement binding is covered by a refusal at the public input constraint, `ringkey.Bound.RefuseStatement` or `ringtest.RequirePublicInputBound`. That refusal proves the binding of the moved value and never a predicate.
- A shape, constant or count pinned against Rust has no refusal case. Its row stays partial with "pin only".
- A real Groth16 test is listed where it adds a case: `prover/ring/prove_test.go` (needs `REQUIRE_RING_KEYS` or installed keys), and the Rust `--features proofs` tests under `program-tests/custom-ring/tests`.

Go test paths are relative to `prover/`. Rust paths are relative to the repository root. A test cell names `file::Test` and, after a slash, the subtest. Every path names code of this tree. The symbol is the anchor, and a line number only helps to find it.

Kinds:

- **bind**: a statement element or wire equals a value the circuit derives from other wires.
- **range**: a value lies in a bound, or has one canonical encoding.
- **domain**: a hash or key schedule takes a tag no other use takes.
- **gate**: a selector or a bit switches a section or a rail.
- **member**: a value is in a set, a tree, a run or a list, or is proven absent.
- **conserve**: a sum or a total equals another.
- **order**: slots or leaves keep a fixed order.

Severity:

- **C**: spend authorization, value, policy enforcement, or the auditor's recovery of a settled note.
- **H**: a value the program or a reader acts on, an encoding another language must match, or privacy of a hidden owner.
- **M**: shape, capacity or a refusal of a malformed witness that no other check would let through.

To update a row, read the constraint and the test assertions, run `go test ./circuits/... ./ring/...` from `prover/`, then change the row. A new predicate takes the next free id of its family. A row whose code moved keeps its id and changes its source line. `INSUFFICIENT_INFO: <what is missing>` marks a claim the code cannot settle. `SPEC_DIVERGENCE: <code> vs <document>` marks a disagreement. Neither is resolved in this file.

## Transfer

Source: [transfer.go](transfer/transfer.go), [input.go](transfer/input.go), [owners.go](transfer/owners.go), [shapes.go](transfer/shapes.go). Statement builder: `TransferStatement::elements` in `program-libs/interface/src/proof/statement.rs`.

One key serves every rail. The program writes the rail bits from the instruction tag, the ring mode and the frame flags. The circuit holds the bits to one rail.

| Rail | `in_proof` | `hidden` | `delegate` | Input owner predicate | Rows ordered | Policy gates | Run |
|---|---|---|---|---|---|---|---|
| Signer, public owners | 0 | 0 | 0 | counted run member | yes | from statement | program run |
| In-proof owner | 1 | 0 | 0 | run member or `sender` | yes | from statement | program run |
| Hidden sender | 0 | 1 | 0 | run member or owner of input 0 | yes | from statement | owner of input 0 stays out |
| Delegate | 0 | 0 | 1 | none | no | all off | empty |

- The circuit does not refuse the zero key. `TestMergeRefusesTheZeroKey` solves a zero-key merge under a row that holds `Poseidon(0)` and refuses it only without such a row. "No zero-key merge proves" in the header of `merge.go` holds because no row ever holds the zero key: `RegisterKeyCircuit` refuses a zero secret and Storage refuses `nullifier_pk = Poseidon(0)`.
- No constraint ties `RecipientKey` to the owner's viewing key. The tracking leaf holds a viewing hash, and `TrackingOpening.Resolve` does not return it. The auditor reads `RecipientKey` from the envelope, and the owner's wallet rebuilds the output from SPP's ciphertext (INV-CIRC-MERGE-08).

## What the circuits do not prove

Each item below is a fact of the code. An auditor needs it as the edge of what a verified proof says.

- **Non-exit tags, payloads and replies.** No ring constraint reads a slot's tag, a payload or reply metadata. SPP's external data hash binds their bytes. `docs/spec/crypto/disclosure.md` "Discovery".
- **The recipient key choice.** No constraint ties a slot's `RecipientKey` or a merge's `RecipientKey` to the intended recipient. The auditor reads each key from its stream.
- **Freshness.** No constraint holds `TxViewingSk`, a salt, a merge or register key `EphSk`, or `ApprovalBlinder` fresh. A resend under one first nullifier repeats `TxViewingSk`, and the salt alone parts the keystreams (`shared/envelope.go:54`).
- **Statement-only elements.** `net_k` (`PublicAmounts`) of the transfer statement, `party_0 .. party_4` off the hidden rail, the zero `delegate_asset` off the delegate rail, `curator_root` while no foreign source is screened, the register key `ring_id` and `member`, and the merge `payer` enter only the statement. The program derives each one. No ring constraint gives them a meaning.
- **SPP's guarantees.** The ring proof takes as given that SPP authorizes each spend, derives each nullifier, conserves each asset, range checks each input amount, holds each output's ring id to zero or the ring's, and derives each output blinding from the seed the ring proof fixes. The comparator bound and INV-CIRC-TRANSFER-22 rely on these.
- **Nullifier links.** No statement element carries a nullifier but `n0`. No constraint binds a published nullifier to an opened input. The auditor links them off chain, and `R` is its count check (INV-CIRC-AUDIT-27).
- **Address inputs.** No ring input slot opens an address. The address chain is a private witness that only `private_tx_hash` checks (INV-CIRC-TRANSFER-22).
- **Root age.** No circuit sees a root's revision. The program serves each root within its grace and refuses a tracking root below a salted source's floor.
- **The derivation of enrolled secrets.** `RegisterKeyCircuit` holds the secret and the salt nonzero and sealed. It does not prove they came from the wallet's derivation.
- **The payer of a merge.** No constraint holds the payer apart from the merged owner.
- **The zero key in a merge.** The merge circuit admits a zero-key output under a row that holds the zero key (INV-CIRC-MERGE notes). Registration is what keeps such a row out.
- **A dummy slot's owner wires.** `OwnerPkHash` and `NullifierPk` of a dummy slot are free, and every reader masks them by the UTXO bit (INV-CIRC-AUDIT notes).
- **The public apply key and private writes.** `ApplyRecordsCircuit` accepts a write to a private list. Storage selects the private key for a nonzero private write bitmap (INV-CIRC-APPLYREC notes).
- **Table validity.** The circuit decodes any table that hashes to `policy_hash`. Polarity, the source map and the guard tags are checked by the program at write time.
- **Withdrawal leg amounts.** No constraint range checks a leg amount. A leg at or past `2^64` opens no `withdrawal_hash` the program builds (`TestWithdrawalLegBindsTheSettledAmount`).
