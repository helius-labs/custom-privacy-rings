# Ring client test invariants

Coverage specification for `zolana-ring-client`, in the form of the
[spr-transaction checklist](../../../zolana/sdk-libs/transaction/tests/INVARIANTS.md).
It lists Critical and High rules only. Rust tests implement its claims. The TypeScript twin of
each row is in [the TypeScript checklist](../../ts/test/INVARIANTS.md), and the key primitives
the client calls are in [the keys checklist](../../keys/tests/INVARIANTS.md).

## Reading and maintaining the checklist

IDs are stable. Never renumber a row, and never give a deleted row's ID to a new rule. Each row
states one observable requirement, not the loop that meets it. Each row ends with the source
file and the function that enforces the rule. The file is relative to `src/` unless it starts
with `sdk-libs/`. A bare function name is in a file of the section's Source line. Every path names
code of this tree. The symbol is the anchor, and a line number only helps to find it.

A test reference names an assertion that fails when the rule breaks. A bare file name is a file
in this directory. A path that starts with `src/` is an inline test of this crate. A path that
starts with `sdk-libs/`, `cli/` or `program-tests/` is relative to the repository root. A
reference that starts with `::` is a test in the file the cell named before it. A vector case,
for example owner vector `thief`, is a case of a pinned `test-vectors/rpc/relay_*_messages.json`
file. The Rust test that pins it and the TypeScript test both assert its verdict.

- `[x]` Covered: a direct assertion exists and its test target passes.
- `[ ]` Partial: some assertions exist. The row states the missing case.
- `[ ]` Missing: no test asserts the rule. The row is a test work item.

Kinds: **pre** is an acceptance or refusal condition, **post** a result on success, **state** a
property that holds at every observable moment, **rollback** what a refusal leaves unchanged,
**wire** an encoding another party reads. Severity: **C** means value, spend authority or a
signature given to the wrong frame. **H** means a leaked secret, a note lost to its owner, or an
encoding another party refuses.

`INSUFFICIENT_INFO` marks a rule the code alone cannot settle. `SPEC_DIVERGENCE` marks code that
differs from `docs/spec.md` or `docs/design/*.md`, with both locations.

To update a row, read the production function and the test assertion, then change the evidence.
A test that only round trips a derived serialization is no coverage. A test helper may build a
valid fixture, but it must not also compute the expected result of the rule under test.

## Open questions, not coverage claims

- SPEC_DIVERGENCE: `src/state/viewing_history.rs:286` (`request_tag`) mints in every state, and
  only `src/state/anonymous_wallet.rs:391` (`update_history`) refuses the store during a recovery.
  [Audit and recovery](../../../docs/design/audit-and-recovery.md) says the wallet refuses the
  mint itself. See INV-CLIENT-SYNC-23.
- SPEC_DIVERGENCE: `src/rpc/wallet_activity.rs:40-55,94-105` gives a co-owner its own outputs
  alone and carries no payload error. [Spec](../../../docs/spec.md) section 8 step 4.3 gives a
  confidential spender every output, payload error and withdrawal. See INV-CLIENT-RPC-24.
- INSUFFICIENT_INFO: no function of this crate verifies the service signature of a
  `createAuditorKey` reply or a `coSignTransaction` reply. The CLI does, in
  `cli/src/runtime/ring_rpc.rs`.
- INSUFFICIENT_INFO: member recovery puts the member's zero-key notes into
  `RecoveredNotes::utxos` with no exposure mark (`src/audit/recover.rs:148`). The code read here
  does not show whether a delegate stage refuses them or names the exposure.
- INSUFFICIENT_INFO: `RingDepositBatch::legs` adds output amounts with `saturating_add`
  (`src/transfer/deposit.rs:391`). No test shows which check refuses a batch whose outputs of one
  asset source pass `u64::MAX`.
- `AnonymousRingTransfers` applies one `TransferTags` value to every payment it prepares
  (`src/transfer/wallet_payment.rs:38,145`), so two payments publish one sender tag and link to
  each other. `ViewingHistory::select` reserves the next index only when the caller stores the
  history it returns.
- The delegate check skips a slot whose record opens as a dummy. Only the ring proof binds that
  record to the dummy commitment of its slot.
- INV-CLIENT-RELAY-46 reads only the notes the caller passes in `OwnerApproval::known_notes`. A
  wallet that has not synced a note cannot refuse a frame that spends it.
- The delegate request text does not cover the transaction viewing secret
  (`src/rpc/authority_transfer.rs:142-191`). INV-CLIENT-RELAY-19 refuses a frame under any other
  key.
- The `createAuditorKey` text names no service key (`src/rpc/mod.rs:952-962`), so one signed
  request is valid at every Ring RPC of the cluster until its timestamp expires.
- `ScanCommit::commit_on` checks the starting history and not the wallet revision
  (`src/state/anonymous_wallet.rs:117`). A tag sync read before `confirm_claim` adds the confirmed
  claim again.
