# Ring TypeScript SDK test invariants

Coverage specification for `@heliuslabs/zolana-custom-rings`. It maps every row of
[the client checklist](../../client/tests/INVARIANTS.md) and of
[the keys checklist](../../keys/tests/INVARIANTS.md) to the TypeScript source that enforces the
same rule and the test that covers it. The Rust row holds the statement, and this file does not
repeat it. The last section lists the Critical and High rules that only TypeScript has.

## Reading and maintaining the checklist

A mapping row has four columns. **Rust ID** names the Rust row. **TypeScript source** names the
file under `src/` and the function that enforces the rule. **Twin** is one of these values.

- `same`: TypeScript enforces the rule of the Rust row.
- `differs`: TypeScript enforces a related rule that accepts or refuses other inputs. The
  coverage cell starts with how it differs.
- `none`: TypeScript has no twin. The row is a gap.
- `rust-only`: the rule runs where only Rust runs, in Ring RPC or the record writer.

A test reference is a path relative to this directory, then `::` and the `it` title as written.
When two tests share a title, the `describe` title comes first, then `›`. A reference that starts
with `::` is a test in the file the cell named before it. `$name`, `%s` and `${testCase.name}`
are the templates of a vitest loop. A vector case, for example owner vector `thief`, is a case of
a pinned file under `test-vectors/` that the Rust test writes and the TypeScript test reads.
Every path names code of this tree. The symbol is the anchor, and a line number only helps to find
it.

- `[x]` Covered: a direct assertion exists and fails when the rule breaks.
- `[ ]` Partial: some assertions exist. The row states the missing case.
- `[ ]` Missing: no test asserts the rule. The row is a test work item.

A TypeScript-only row has the columns of the Rust checklists and an ID `INV-TS-<AREA>-<NN>`.
IDs are stable. Never renumber a row, and never give a deleted row's ID to a new rule. Kinds and
severities are those of [the client checklist](../../client/tests/INVARIANTS.md), and **frame** is
what an operation does not change.

To update a row, read the TypeScript function and the test assertion, then change the evidence.
When a Rust row changes, check its twin in the same change.

## Open questions, not coverage claims

- An indexer stops `syncRingWallet` with a ring merge row whose first nullifier is outside the
  field, since core `mergeOutputKey` refuses the value with `KEYPAIR_POSEIDON`. Rust skips that
  merge alone. See INV-CLIENT-SYNC-29.
- Member recovery takes no required slot (`src/operations/workflow/recover.ts:46,124`), so an
  indexer behind the chain can report a spent note as unspent. See INV-CLIENT-SYNC-38.
- `openRingSealedKey` and `openListSalt` (`src/operations/management/register-key.ts:95-102,159-166`)
  do not check the opened salt against the row's list tag, and `privateListKey`
  (`src/protocol/membership/private-list.ts:17-22`) builds a set key under any nonzero salt. A
  write under a wrong salt lands where no proof reads it. See INV-CLIENT-RECORD-08 and
  INV-CLIENT-RECORD-14.
- `RingAddress.enrolled` (`src/crypto/keys/ring-address.ts:68-74`) takes any canonical salt from
  the caller and can pair a holder's address with another salt. See INV-KEYS-ADDR-06.
- `encodeRingBodyOutput` (`src/protocol/transaction/output.ts:41-53`) accepts a body shorter than
  a record, which every reader drops. Rust refuses it with `OutputBodyLength`.
- `LocalRingKeys.fromKeypair` (`src/state/ring-keys.ts:102-109`) takes the keypair's current
  viewing key as the list root. A rotated keypair derives another list salt than the enrolled
  one, as Rust `RotatingRingKeys::new` does.
- Secrets sit in enumerable fields that `JSON.stringify` and `util.inspect` print: the delegate
  nullifier secret (`src/rpc/ring-rpc/wallet-reads.ts:182`), the transaction viewing key of an
  authority transfer request (`src/protocol/ring-rpc/ring-rpc-types.ts:356`), the list salts
  (`src/rpc/ring-rpc/client.ts:869-880`), note blindings, `AuditEnvelope.txViewingSecret` and
  `MergeRecord.seed` (`src/protocol/codec/audit-stream.ts:84-122`). See the REDACT twins.
